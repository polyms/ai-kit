# Comms

Use [communication-templates.md](communication-templates.md) and the shared work artifact standard
(`docs/agents/work-artifact-standard.md`).

1. Identify recipient, channel, purpose, language, relationship and desired tone from available context.
2. Read the relevant discussion or decision. Distinguish what is agreed, proposed, pending or verified.
3. Choose the smallest sufficient format. Lead with the answer or purpose, then necessary context,
   action and deadline only if known. Keep messages natural; avoid canned filler and needless detail.
4. Preserve factual meaning in bilingual versions; do not translate technical identifiers or change
   commitments. Use one prose language per version. For a simple rewrite, preserve the user's intent.
5. Draft first unless the user explicitly requests sending or posting. Use an authorized integration
   only for the requested recipient or ticket. Report actual delivery status, not assumed success.

**Done when:** The message can be sent as written, matches the audience and does not create unsupported
promises, approvals, estimates or claims of completed work.

Use `docs` for substantial standalone documents, `track` for ticket state changes and `business`
for underlying analysis. Communication does not itself approve a proposed decision.
