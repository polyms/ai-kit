# Sprint planning

**Use when:** The user requests a backlog review, effort allocation or sprint proposal. Read the
composition protocol.

| Stage | Input / output | Run when |
| --- | --- | --- |
| track | Project/filter -> latest backlog snapshot | Current work, status or owners must be retrieved. |
| review | Backlog/requirements -> scope and risk findings | Missing AC, dependencies or scope contradictions need review. |
| plan | Bounded scope, team and calendar -> feasible delivery plan | Capacity or scheduling is requested. |
| task | Accepted scope/plan -> new work drafts | Genuinely missing work items need drafting. |

**Gates:** Do not interpret an incomplete page as the complete backlog. Do not estimate unresolved
scope as confirmed or equate person-days with elapsed days. If capacity is unknown, state
assumptions or produce a range, not a guaranteed sprint. Existing issues stay existing; use track
for authorized updates to assignment, due date or priority rather than creating duplicates.
A proposed schedule does not authorize bulk edits.

**Finish:** Report capacity, prioritized proposed scope, excluded work, dependencies and blockers.
Separate suggested changes from verified tracker updates. Stop before unrequested scheduling or
assignment.
